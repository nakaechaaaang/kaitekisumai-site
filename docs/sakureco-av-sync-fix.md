# サクレコ 画面共有時の音声・映像ズレ修正（2026-07-02）

## 症状
画面の共有を含む録画（「画面のみ」「画面＋カメラ」）で、音声と映像がずれる。
カメラのみの録画では発生しない。

## 原因（3点）

### 1. 画面共有の映像は可変フレームレート（主原因）
`getDisplayMedia` の映像トラックは「画面の内容が変化した時だけ」フレームを生成する。
静止画面が続くと数秒〜数十秒フレームが来ない一方、音声は等速で流れ続ける。
この不等間隔な映像をそのまま MediaRecorder（現行 Chrome では `pickMime()` が
MP4 コンテナを最優先で選択）へ渡すと、コンテナ内のタイムスタンプが不整合になり、
再生時に音声と映像がずれる。カメラは常に等間隔 30fps のフレームを供給するため、
「画面共有の時だけずれる」という症状と一致する。

### 2. 録画中はタブが裏に回り、合成ループが間引かれる（画面＋カメラ）
画面共有中はユーザーが別ウィンドウで作業するため、サクレコのタブは非表示になる。
旧実装はタブ非表示時に `setTimeout(loop, 33)` へフォールバックしていたが、
Chrome は非表示タブのタイマーを最低1秒間隔に間引くため、合成映像が約1fpsまで
低下し、音声だけが先へ進む。

### 3. 音源1本でも WebAudio を経由していた
マイクのみの場合でも `AudioContext` → `createMediaStreamDestination` を通していた。
WebAudio は映像と別のオーディオハードウェアクロックで動き、出力遅延も乗るため、
不要な経由は固定オフセットと長時間録画でのドリフトの一因になる。

## 修正内容（sakureco/index.html）

1. **「画面のみ」モードも Canvas 経由で一定30fpsに変換して記録**
   （アスペクト比維持・黒帯レターボックス）。MediaRecorder には常に等間隔の
   フレームが供給され、コンテナのタイムスタンプが安定する。
2. **描画ループを Web Worker のタイマー駆動に変更**（`startTicker()`）。
   Worker のタイマーはタブ非表示でも間引かれないため、裏で作業中も30fpsを維持。
   Worker が使えない環境のみ従来の rAF/タイマー方式にフォールバック。
3. **音声トラックが1本だけの場合は WebAudio を通さず素のトラックを記録**。
   ミックスが必要な場合（マイク＋画面の音）のみ従来どおり WebAudio で合成。

## 検証
- `node --check` によるスクリプト構文検証: OK
- ヘッドレス Chromium（Playwright）で「画面のみ」「画面＋カメラ」両モードの
  実録画スモークテスト: 録画5秒 → プレビュー約5.3〜5.4秒、映像トラック30fps固定、
  マイク音声はWebAudio非経由の素のトラック、音声デコード確認、ページエラーなし。
